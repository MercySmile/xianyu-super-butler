# 同一规格组合发送卡密与固定文本

同一个商品规格可以绑定一个主发货内容，再附带多份固定文本。比如「账号和资源下载器」套餐：每份消耗一组账号，附上重复使用的下载地址和教程。

## 配置步骤

1. 在「卡密库存」建立账号库存：普通「批量数据」仍是一行一个库存；「分组卡密」则是一整套多行账号资料一个库存。
2. 在「卡密库存」建立「固定文字」，例如「下载地址」「使用教程」。固定文字可以被多个商品规格复用。
3. 打开「商品与发货 → 对应商品的发货策略」，在需要组合交付的规格中，把「主发货内容 / 库存」选为账号库存。
4. 点击「添加固定文本」，选择下载地址；再次点击可追加教程。用「上移」调整附带文本的先后顺序，用删除按钮移除。这样就不用把同一份教程复制进每条账号库存。
5. 设置「每购买 1 件发货份数」，保存策略。无需附带文本的规格不添加即可。

## 发货结果

一份完整交付按以下顺序组合，内容之间保留空行：

```text
账号资料（主库存中的一条 / 一组）

下载地址（固定文字）

使用教程（固定文字）
```

固定文本不扣库存。主卡密仍按「商品数量 × 每件发货份数」消费；每份卡密都附带选中的全部固定文本。未开启商品「多数量」时，商品数量系数仍按原有规则取 1。

例如开启多数量、每件 1 份，买 2 件就消耗 2 条 / 组卡密，每份都附带下载地址和教程。文本较长时会分段发送，任何一段发送失败都不会被当成整单发送成功。

主内容也可以选择固定文字，再附带其他固定文字；这种组合没有消耗型库存。API 与图片主内容沿用原来的单内容发货方式。

## 库存与配置保护

- 如果主卡密不足以满足整单数量，不扣减库存，也不单独交付附带文本。
- 附带内容必须是当前用户拥有、已启用、内容非空的固定文字；同一规格不能重复选择同一份内容。
- 附带文本被停用、清空或改为其他类型后，相关规格会显示配置不完整，并在获取卡密前拦截发货。
- 正被规格使用的附带文本不能直接在后台删除，需要先移除绑定。
- 修改固定文字后，新订单使用更新后的内容；正在处理的订单沿用已取得的内容快照。
- 同一个主库存可以被多个规格共享，这些规格会共同消费该库存。

更新后重启后端，数据库会自动增加组合配置字段，原有单内容绑定保持有效。仓库包含已构建的前端；直接 Python 部署更新代码后重启并刷新浏览器即可，Docker 部署需重新构建容器。

新增 API 字段为每个规格的 `fixed_text_card_ids`，是按发送顺序排列的固定文字卡密 ID 列表；省略或传空列表表示只发主内容。商品规格的文字 / SKU 匹配规则不变。
